Simulation

Parameters

UnitCellMC.SimulationParameters — Type
SimulationParameters{T<:Real}

Validated parameters controlling a single Monte Carlo simulation run: the temperature and the sweep counts for thermalization, measurement, and binning.

Fields

  • T::T: Temperature; must be strictly positive.
  • n_thermalization::Int: Number of thermalization (equilibration) sweeps before measurements begin; must be non-negative.
  • n_measurements::Int: Total number of measurement sweeps; must be positive and divisible by n_bins.
  • n_unmeasured::Int: Number of sweeps between measurements (decorrelation steps); must be non-negative. Rather than guessing, use autotune_binning, which estimates the integrated autocorrelation time from a short pilot run and recommends n_unmeasured and a bin size via recommended_binning.
  • n_bins::Int: Number of bins measurements are grouped into for error estimation; must be at least 2.

n_measurements and n_bins are checked with validate_binning, the same rule MeasurementContainer applies, and run_simulation requires the container it fills to have the matching bin size n_measurements ÷ n_bins.

Construct with SimulationParameters(T, n_thermalization, n_measurements, n_unmeasured, n_bins); all fields are validated at construction time.

UnitCellMC.steps_per_sweep — Function
steps_per_sweep(algorithm, geometry)

Return the number of step! updates that constitute one Monte Carlo sweep for algorithm on geometry.

For local-update algorithms (the default, e.g. MetropolisAlgorithm and GlauberAlgorithm) a sweep is geometry.n_sites single-site updates, so that on average every site is updated once per sweep. For cluster algorithms (WolffAlgorithm, SwendsenWangAlgorithm) a single cluster update already moves a macroscopic fraction of the lattice, so a sweep is exactly one call to step!.

Extend this function to change the sweep size for a custom algorithm.

UnitCellMC.MC_Sweep! — Function
MC_Sweep!(algorithm, model, geometry, state, container, T, stats;
    rng = Random.default_rng()) on `state` at temperature `T`, accumulating

per-update algorithm diagnostics into stats.

The number of step! calls per sweep is determined by steps_per_sweep: geometry.n_sites for local-update algorithms, one cluster update for cluster algorithms. After each update, diagnostic_values is evaluated and the values matching container.diagnostics are recorded into the corresponding UpdateStatistics in stats, which must be one per diagnostic (see run_simulation).

Arguments

  • algorithm: The update algorithm to use.
  • model: The model defining couplings/energetics.
  • geometry: The lattice geometry.
  • state: The current configuration, mutated in place.
  • container: A MeasurementContainer; only its diagnostics field is used to select which diagnostics to accumulate.
  • T: Temperature passed to step!.
  • stats: Vector of UpdateStatistics, one per entry in container.diagnostics. Reset at the start of the sweep.
  • rng: Random number generator passed to every step!.

Returns

stats, containing the sweep-averaged diagnostic values.

UnitCellMC.run_simulation — Function
run_simulation(algorithm, model, geometry, state, container, parameters;
    rng = Random.default_rng()) Monte Carlo simulation and return `container` filled

with the binned measurements described by parameters.

The sequence of sweeps is:

  1. parameters.n_thermalization warmup sweeps (simply calls to MC_Sweep!), with no measurements taken;
  2. parameters.n_measurements measurement sweeps, each followed by a call to measure! with the sweep-averaged diagnostics;
  3. parameters.n_unmeasured decorrelation sweeps after each measurement to reduce autocorrelation.

One sweep consists of steps_per_sweep calls to step!: geometry.n_sites single-site updates for MetropolisAlgorithm and GlauberAlgorithm, or a single cluster update for WolffAlgorithm and SwendsenWangAlgorithm.

Arguments

  • algorithm: The update algorithm to use (e.g. MetropolisAlgorithm()).
  • model: The model defining couplings/energetics.
  • geometry: The lattice geometry.
  • state: The current configuration, mutated in place.
  • container: The MeasurementContainer to fill, mutated in place.
  • parameters: A SimulationParameters controlling temperature and sweep counts.
  • rng: Random number generator for every update. Defaults to the task-local global RNG, so calling Random.seed!(seed) beforehand makes the run reproducible; pass e.g. Random.Xoshiro(seed) for an explicit stream.

Throws

ArgumentError if container and parameters do not describe the same binning, or if container requests diagnostics that algorithm does not provide (see validate_run). The check runs before any sweep.

Returns

container, ready for post-processing with analyze.

UnitCellMC.validate_run — Function
validate_run(algorithm, container, parameters)

Check that container can record the run described by parameters with algorithm, so that run_simulation fills exactly parameters.n_bins complete bins and never fails mid-run.

The container's bin size must equal parameters.n_measurements ÷ parameters.n_bins; otherwise measurements would be grouped into a different number of bins than requested, and a trailing partial bin would be silently dropped. Every diagnostic the container records must be among available_diagnostics(algorithm).

Throws

ArgumentError if either condition fails.

Returns

nothing.

UnitCellMC.sweep_Ts — Function
sweep_Ts(algorithm, model, geometry, state,
    n_thermalization, n_measurements, n_unmeasured, n_bins, Ts;
    simulated_annealing = true, n_runs = 1, measurements = Symbol[],
    diagnostics = Symbol[], time_series = :scalars, root = "results",
    rng = Random.default_rng(), seed = recorded_seed(rng))

Run a temperature sweep: run_simulation at each temperature in Ts, followed by analyze, and save the combined results with save_sweep_results.

With n_runs > 1, n_runs independent simulations are performed at each temperature and their bins are merged with merge_containers before analysis, so the returned error bars reflect run-to-run variance. The merged container holds n_runs * n_bins bins per temperature. Runs share an annealing trajectory: with simulated_annealing = true (default) each run carries its own configuration between temperatures (state seeds run 1; best practice: order Ts from highest to lowest); with simulated_annealing = false every run is re-initialized from a fresh random state at every temperature.

The runs execute in parallel over Julia threads: start Julia with --threads auto (or set JULIA_NUM_THREADS) to use more than one.

Reproducibility

Before any threads start, one seed per run is drawn from rng and each run gets its own Random.Xoshiro generator, which it keeps for the whole sweep (state initialization and every update at every temperature). A run therefore consumes the same random stream whichever thread executes it, so the results are bit-for-bit identical for any thread count. To reproduce a sweep, call set_global_seed! at the start of the script and keep the inputs, including the initial state, the same. The seed is written to the sweep's metadata.txt (as unknown if the global RNG was seeded some other way, e.g. with Random.seed!), so every results folder records how to recreate it. An explicit generator such as rng = Random.Xoshiro(seed) works too; pass seed alongside it to have it recorded.

A new SimulationParameters is created for every temperature (shared by all runs at that temperature), and a new MeasurementContainer is created for every temperature and run.

Arguments

  • algorithm: The update algorithm to use.
  • model: The model defining couplings/energetics.
  • geometry: The lattice geometry.
  • state: The starting configuration for run 1; reused across temperatures when simulated_annealing = true.
  • n_thermalization: Warmup sweeps per run and temperature.
  • n_measurements: Measurement sweeps per run and temperature.
  • n_unmeasured: Decorrelation sweeps between measurements.
  • n_bins: Number of bins per run for jackknife error estimation.
  • Ts: Temperatures to simulate.
  • simulated_annealing: Carry each run's state between temperatures (default true).
  • n_runs: Number of independent runs averaged at each temperature (default 1); must be at least 1.
  • measurements: Optional measurement names to enable in each container.
  • diagnostics: Algorithm diagnostic names to record per sweep.
  • time_series: Which observables keep their unbinned history for the autocorrelation analysis in analyze; see MeasurementContainer. The default :scalars skips the correlation-function vector; use :none to store nothing.
  • root: Base directory passed to save_sweep_results.
  • rng: Random number generator from which the per-run seeds are drawn. Defaults to the task-local global RNG, which set_global_seed! (or Random.seed!) controls.
  • seed: Seed recorded in metadata.txt. Defaults to the global_seed when rng is the global RNG, and to nothing (recorded as unknown) for an explicit rng.

Throws

ArgumentError if n_runs is less than 1, if any temperature in Ts or the sweep counts are rejected by SimulationParameters, or if the measurements, diagnostics, or time_series arguments are rejected by MeasurementContainer or validate_run. All of these are checked on the calling task before any thread starts, so they are thrown directly rather than wrapped in a CompositeException.

Returns

A vector with one analyze result per temperature in Ts.

UnitCellMC.merge_containers — Function
merge_containers(containers)

Merge the binned measurement data of several filled MeasurementContainers — e.g. from n_runs independent run_simulations at the same temperature — into a single container whose data holds the concatenation of all runs' bins. Analysis on the merged container therefore pools all runs, and error estimates reflect the variance between independent runs as well as within them.

The containers must record the same observables and diagnostics, and keep the same unbinned time series (e.g. built with identical measurements/diagnostics/time_series arguments); an ArgumentError is thrown otherwise. The time series are concatenated too, with each run's length stored in chain_lengths so autocorrelations never straddle runs.

Returns

A new MeasurementContainer with length(containers) * n_bins completed bins, ready for analyze.

UnitCellMC.autotune_binning — Function
autotune_binning(algorithm, model, geometry, state, Ts;
                 n_thermalization = 1_000, n_pilot = 5_000,
                 measurements = Symbol[], observables = nothing,
                 bin_factor = 10, n_unmeasured = nothing,
                 window = 6.0, max_lag = nothing,
                 rng = Random.default_rng())

Choose n_unmeasured and the bin size from the data instead of guessing: run a short pilot simulation at each temperature in Ts, measuring after every sweep, estimate the integrated autocorrelation time τ (in sweeps) of each observable with autocorrelation, and convert the slowest one into (bin_size, n_unmeasured) with recommended_binning.

Autocorrelation times grow strongly near a phase transition (critical slowing down, τ ∼ L^z) and, for local updates, at low temperature, so pass every temperature of a planned sweep_Ts (or at least those near the critical point and the lowest one). The pilot visits Ts in the order given and carries state from one temperature to the next, like sweep_Ts with simulated_annealing = true; state is mutated.

Keywords

  • n_thermalization: Warmup sweeps before each pilot measurement run.
  • n_pilot: Pilot measurement sweeps per temperature. The default maximum lag (n_pilot ÷ 10) resolves τ up to about n_pilot / 60 sweeps.
  • measurements: Optional measurements to include in the pilot, as for MeasurementContainer (e.g. [:abs_magnetization]).
  • observables: Names of the observables whose τ determines the recommendation. Only these keep an unbinned history during the pilot. Default: all scalar observables (vector-valued ones such as :correlation are memory-hungry and must be listed explicitly). For the zero-field Ising model you may want to exclude the signed :magnetization, whose τ at low temperature is the (often astronomically long) time to tunnel between the ±m ground states rather than the relaxation time of the physical quantities.
  • bin_factor, n_unmeasured: Passed to recommended_binning.
  • window, max_lag: Passed to autocorrelation.
  • rng: Random number generator for the pilot runs. Defaults to the task-local global RNG, so Random.seed! makes the recommendation reproducible.

Returns

A named tuple with fields

  • bin_size, n_unmeasured: The recommendation. Use n_measurements = bin_size * n_bins in production runs.
  • tau: The slowest integrated autocorrelation time used (in sweeps).
  • T, observable: Where tau was found.
  • per_temperature: For each T in Ts, a Dict mapping observable name to its AutocorrelationResult (times in sweeps).

If an observable's τ could not be resolved within the pilot, a warning is emitted and its lower bound (tau_lower_bound) is used, so the recommendation may still be too small: increase n_pilot in that case. Observables that did not change at all during the pilot (frozen dynamics) are ignored with a warning.

Throws

ArgumentError for invalid arguments, or if no selected observable fluctuated during the pilot (so no autocorrelation time could be estimated).

Reproducibility

UnitCellMC.set_global_seed! — Function
set_global_seed!(seed = rand(Random.RandomDevice(), UInt32))

Seed Julia's global (task-local) RNG with seed via Random.seed! and record it, so that the result writers (save_results, save_sweep_results, and therefore sweep_Ts) store it in metadata.txt. Call it once near the start of a script: every random number drawn afterwards (initial states, autotuning pilots, and all parallel runs of sweep_Ts) then follows from seed, and rerunning the script with the same seed, inputs, and Julia version reproduces the results exactly, for any number of threads.

Without an argument a fresh seed is drawn from the operating system's entropy source, so even an unplanned run can be recreated from its metadata.

Seeding with Random.seed! directly also makes runs reproducible, but the seed is then not known to UnitCellMC and is recorded as unknown (or, if set_global_seed! was called earlier in the session, as that earlier seed, which no longer describes the run), so prefer this function.

Returns

The seed that was set.
