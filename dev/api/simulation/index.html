Simulation

Parameters

UnitCellMC.SimulationParameters — Type
SimulationParameters{T<:Real}

Validated parameters controlling a single Monte Carlo simulation run: the temperature and the sweep counts for thermalization, measurement, and binning.

Fields

  • T::T: Temperature; must be strictly positive.
  • n_thermalization::Int: Number of thermalization (equilibration) sweeps before measurements begin; must be non-negative.
  • n_measurements::Int: Total number of measurement sweeps; must be positive and divisible by n_bins.
  • n_unmeasured::Int: Number of sweeps between measurements (decorrelation steps); must be non-negative. Rather than guessing, use autotune_binning, which estimates the integrated autocorrelation time from a short pilot run and recommends n_unmeasured and a bin size via recommended_binning.
  • n_bins::Int: Number of bins measurements are grouped into for error estimation; must be at least 2.

n_measurements and n_bins are checked with validate_binning, the same rule MeasurementContainer applies, and run_simulation requires the container it fills to have the matching bin size n_measurements ÷ n_bins.

Construct with SimulationParameters(T, n_thermalization, n_measurements, n_unmeasured, n_bins); all fields are validated at construction time.

UnitCellMC.MC_Sweep! — Function
MC_Sweep!(algorithm, model, geometry, state, container, T, stats;
    rng = Random.default_rng(), workspace = nothing)

Perform one Monte Carlo sweep on state at temperature T, accumulating per-update algorithm diagnostics into stats.

The number of step! calls per sweep is determined by steps_per_sweep: geometry.n_sites for local-update algorithms, one cluster update for cluster algorithms. After each update, diagnostic_values is evaluated and the values matching the container's diagnostic names (its D type parameter) are recorded into the corresponding UpdateStatistics in stats, which must be one per diagnostic (see run_simulation). The per-update loop is delegated to sweep_steps!, whose default method calls step!; model/algorithm pairs with a fused fast path (single-orbital IsingModel under MetropolisAlgorithm with RandomProposal) override it.

Arguments

  • algorithm: The update algorithm to use.
  • model: The model defining couplings/energetics.
  • geometry: The lattice geometry.
  • state: The current configuration, mutated in place.
  • container: A MeasurementContainer; only its diagnostic names are used to select which diagnostics to accumulate.
  • T: Temperature passed to step!.
  • stats: Tuple of UpdateStatistics, one per requested diagnostic. Reset at the start of the sweep.
  • rng: Random number generator passed to every step!.
  • workspace: Per-run scratch space passed to step! (see algorithm_workspace); nothing lets step! allocate its own. Cluster algorithms reuse a ClusterWorkspace; local-update algorithms carry a LocalUpdateWorkspace bundling the proposal scheme's site cursor (see SequentialProposal) with the AcceptanceCache of discrete-spectrum models.

Returns

stats, containing the sweep-averaged diagnostic values.

UnitCellMC.run_simulation — Function
run_simulation(algorithm, model, geometry, state, container, parameters;
    rng = Random.default_rng(), shared = shared_workspace(algorithm, model, geometry))

Run a Monte Carlo simulation and return container filled with the binned measurements described by parameters.

The sequence of sweeps is:

  1. parameters.n_thermalization warmup sweeps (simply calls to MC_Sweep!), with no measurements taken;
  2. parameters.n_measurements measurement sweeps, each followed by a call to measure! with the sweep-averaged diagnostics;
  3. parameters.n_unmeasured decorrelation sweeps after each measurement to reduce autocorrelation.

One sweep consists of steps_per_sweep calls to step! (see MC_Sweep!).

Arguments

  • algorithm: The update algorithm to use (e.g. MetropolisAlgorithm()).
  • model: The model defining couplings/energetics.
  • geometry: The lattice geometry.
  • state: The current configuration, mutated in place.
  • container: The MeasurementContainer to fill, mutated in place.
  • parameters: A SimulationParameters controlling temperature and sweep counts.
  • rng: Random number generator for every update. Defaults to the task-local global RNG, so calling Random.seed!(seed) beforehand makes the run reproducible; pass e.g. Random.Xoshiro(seed) for an explicit stream.
  • shared: Deterministic, geometry-only workspace data shared across runs — must be shared_workspace(algorithm, model, geometry) (the default recomputes it). sweep_Ts builds it once and passes it to every run, so the lattice coloring of a colored proposal scheme is not recomputed per (temperature, run).

Throws

ArgumentError if container and parameters do not describe the same binning, if container requests diagnostics that algorithm does not provide (see validate_run), or if state is not the state type expected by model (see validate_model_state). Both checks run before any sweep.

Returns

container, ready for post-processing with analyze.

UnitCellMC.validate_run — Function
validate_run(algorithm, container, parameters)

Check that container can record the run described by parameters with algorithm, so that run_simulation fills exactly parameters.n_bins complete bins and never fails mid-run.

The container's bin size must equal parameters.n_measurements ÷ parameters.n_bins; otherwise measurements would be grouped into a different number of bins than requested, and a trailing partial bin would be silently dropped. The container must not hold a partially filled bin from an earlier (aborted) run — its stale partial sum would otherwise mix into this run's first bin. Every diagnostic the container records must be among available_diagnostics(algorithm).

Throws

ArgumentError if any of these conditions fails.

Returns

nothing.

UnitCellMC.sweep_Ts — Function
sweep_Ts(algorithm, model, geometry, state,
    n_thermalization, n_measurements, n_unmeasured, n_bins, Ts;
    simulated_annealing = true, n_runs = 1, measurements = Symbol[],
    diagnostics = Symbol[], time_series = :scalars, root = "results",
    save = true, rng = Random.default_rng(), seed = recorded_seed(rng))

Run a temperature sweep: run_simulation at each temperature in Ts, followed by analyze. Unless save = false, the combined results are saved with save_sweep_results.

With n_runs > 1, n_runs independent simulations are performed at each temperature and their bins are merged with merge_containers before analysis, so the returned error bars reflect run-to-run variance. The merged container holds n_runs * n_bins bins per temperature. Runs share an annealing trajectory: with simulated_annealing = true (default) each run carries its own configuration between temperatures (state seeds run 1; best practice: order Ts from highest to lowest); with simulated_annealing = false every run is re-initialized from a fresh random state at every temperature (state itself is then unused).

The simulations execute in parallel over Julia threads: start Julia with --threads auto (or set JULIA_NUM_THREADS) to use more than one. With simulated_annealing = true each temperature depends on the previous one, so only the n_runs runs at a temperature execute in parallel. With simulated_annealing = false the (temperature, run) pairs are fully independent, so all length(Ts) * n_runs simulations form a single parallel pool — temperatures are parallelized too, which keeps all threads busy even when n_runs is smaller than the thread count. The trade-off is that every run's MeasurementContainer (including its unbinned time series) is allocated up front and stays alive until the pool finishes, so peak memory scales with length(Ts) * n_runs; with annealing, only n_runs containers are alive at a time.

Reproducibility

Before any threads start, seeds are drawn from rng and turned into one Random.Xoshiro generator per independent simulation: with simulated_annealing = true one per run, kept for the whole sweep (state initialization and every update at every temperature); with simulated_annealing = false one per (temperature, run) pair, used to initialize the state and perform every update of that simulation. Each simulation therefore consumes the same random stream whichever thread executes it, so the results are bit-for-bit identical for any thread count. To reproduce a sweep, call set_global_seed! at the start of the script and keep the inputs, including the initial state, the same. The seed is written to the sweep's metadata.txt (as unknown if the global RNG was seeded some other way, e.g. with Random.seed!), alongside n_runs, simulated_annealing, measurements, diagnostics, and time_series, so every results folder records how to recreate it. An explicit generator such as rng = Random.Xoshiro(seed) works too; pass seed alongside it to have it recorded.

A new SimulationParameters is created for every temperature (shared by all runs at that temperature), and a new MeasurementContainer is created for every temperature and run.

Arguments

  • algorithm: The update algorithm to use.
  • model: The model defining couplings/energetics.
  • geometry: The lattice geometry.
  • state: The starting configuration for run 1; reused across temperatures when simulated_annealing = true. Not used when simulated_annealing = false, where every simulation starts from a fresh random state.
  • n_thermalization: Warmup sweeps per run and temperature.
  • n_measurements: Measurement sweeps per run and temperature.
  • n_unmeasured: Decorrelation sweeps between measurements.
  • n_bins: Number of bins per run for jackknife error estimation.
  • Ts: Temperatures to simulate.
  • simulated_annealing: Carry each run's state between temperatures (default true); when false, every temperature starts from a fresh random state and all length(Ts) * n_runs simulations are independent and execute in a single parallel pool.
  • n_runs: Number of independent runs averaged at each temperature (default 1); must be at least 1.
  • measurements: Optional measurement names to enable in each container.
  • diagnostics: Algorithm diagnostic names to record per sweep.
  • time_series: Which observables keep their unbinned history for the autocorrelation analysis in analyze; see MeasurementContainer. The default :scalars skips the correlation-function vector; use :none to store nothing.
  • root: Base directory passed to save_sweep_results.
  • save: Save the sweep results under root via save_sweep_results (default true). With save = false nothing is written; the returned results are the only output.
  • rng: Random number generator from which the per-simulation seeds are drawn. Defaults to the task-local global RNG, which set_global_seed! (or Random.seed!) controls.
  • seed: Seed recorded in metadata.txt. Defaults to the global_seed when rng is the global RNG, and to nothing (recorded as unknown) for an explicit rng.

Throws

ArgumentError if n_runs is less than 1, if any temperature in Ts or the sweep counts are rejected by SimulationParameters, if the measurements, diagnostics, or time_series arguments are rejected by MeasurementContainer or validate_run, or if simulated_annealing is true and state is not the state type expected by model (see validate_model_state). All of these are checked on the calling task before any thread starts, so they are thrown directly rather than wrapped in a CompositeException.

Returns

A vector with one analyze result per temperature in Ts.

UnitCellMC.tempering_sweep — Function
tempering_sweep(algorithm, model, geometry, Ts,
    n_thermalization, n_measurements, n_unmeasured, n_bins;
    swap_every = 1, measurements = Symbol[], diagnostics = Symbol[],
    time_series = :scalars, states = nothing, root = "results",
    save = true, rng = Random.default_rng(), seed = recorded_seed(rng))

Run a parallel tempering (replica exchange) simulation over the temperature ladder Ts and return a ParallelTemperingResult. Unless save = false, the output is saved with save_tempering_results.

One replica simulates model at each temperature with algorithm — any AbstractAlgorithm works as the inner update, including the cluster algorithms. The simulation proceeds in rounds: one MC_Sweep! per replica (in parallel over threads), followed every swap_every rounds by a serial swap_pass! attempting to exchange the configurations of neighboring temperatures. The sequence of rounds mirrors run_simulation with "sweep" replaced by "round":

  1. n_thermalization warmup rounds with no measurements;
  2. n_measurements measurement rounds, each followed by measure! of every replica into its own MeasurementContainer;
  3. n_unmeasured decorrelation rounds after each measurement.

Swap passes also run during thermalization and decorrelation rounds — they are part of the dynamics, mixing configurations across the ladder so that low-temperature replicas equilibrate through excursions to high temperature. After the run, each replica's container is analyzed with analyze at its own temperature, giving one result per temperature of the same shape as sweep_Ts returns.

Ts must be sorted in ascending order: Ts[1] is the coldest replica. Build a ladder with geometric_ladder and space it so adjacent swap acceptance rates (reported in the result) land near 0.2–0.5.

Reproducibility

Before any threads start, rng seeds one Random.Xoshiro per replica (used for that replica's state initialization and every update at every round) plus one more for the swap passes, which are serial. Each random stream is therefore consumed in a fixed order independent of thread scheduling, so the results are bit-for-bit identical for any thread count. Call set_global_seed! before the sweep and keep the inputs the same to reproduce it; the seed is written to metadata.txt (as unknown if the global RNG was seeded some other way). An explicit generator such as rng = Random.Xoshiro(seed) works too; pass seed alongside it to have it recorded.

Arguments

  • algorithm: The per-replica update algorithm (e.g. MetropolisAlgorithm).
  • model: The model defining couplings/energetics.
  • geometry: The lattice geometry.
  • Ts: The temperature ladder; at least 2 temperatures, sorted ascending.
  • n_thermalization: Warmup rounds before measurements begin.
  • n_measurements: Measurement rounds; must be divisible by n_bins.
  • n_unmeasured: Decorrelation rounds between measurements. Note autotune_binning pilots are ordinary single-temperature runs; its recommended n_unmeasured remains a sensible starting point here, since tempering only shortens autocorrelation times.
  • n_bins: Number of bins per replica for jackknife error estimation.
  • swap_every: Rounds between swap passes (default 1).
  • measurements: Optional measurement names enabled in every container.
  • diagnostics: Algorithm diagnostic names recorded per replica sweep.
  • time_series: Which observables keep their unbinned history; see MeasurementContainer.
  • states: Optional starting configurations, one per temperature, e.g. pre-thermalized states from an earlier run. By default every replica starts from a fresh random state drawn with its own stream.
  • root: Base directory passed to save_tempering_results.
  • save: Save the results under root (default true). With save = false nothing is written; the returned result is the only output.
  • rng: Random number generator from which the per-replica and swap seeds are drawn. Defaults to the task-local global RNG, which set_global_seed! (or Random.seed!) controls.
  • seed: Seed recorded in metadata.txt. Defaults to the global_seed when rng is the global RNG, and to nothing (recorded as unknown) for an explicit rng.

Throws

ArgumentError if fewer than 2 temperatures are given, if Ts is not sorted ascending or contains a non-positive temperature, if swap_every < 1, if the sweep counts fail SimulationParameters validation, if states does not hold exactly one configuration per temperature or one of them is not the state type expected by model (see validate_model_state), or if measurements, diagnostics, or time_series are rejected by MeasurementContainer or validate_run. All checks run on the calling task before any thread starts, so they are thrown directly rather than wrapped in a CompositeException.

Returns

A ParallelTemperingResult: one analyze result per temperature plus the swap attempts, accepts, and acceptance rate of each adjacent temperature pair.

source
UnitCellMC.ParallelTemperingResult — Type
ParallelTemperingResult{R}

The result of a tempering_sweep: the per-temperature analysis of every replica plus the swap statistics of the adjacent temperature pairs.

Fields

  • results::Vector{R}: One analyze result per temperature, in the order of the ladder (results[i] corresponds to temperatures[i]).
  • temperatures::Vector{Float64}: The temperature ladder, ascending; temperatures[1] is the coldest replica.
  • swap_attempts::Vector{Int}: Swap attempts per adjacent pair; swap_attempts[i] counts attempted exchanges of the configurations at temperatures[i] and temperatures[i + 1].
  • swap_accepts::Vector{Int}: Accepted swaps per adjacent pair, same order.
  • swap_acceptance::Vector{Float64}: swap_accepts ./ swap_attempts per adjacent pair (NaN for a pair that was never attempted, e.g. when swap_every exceeds the total number of rounds). Acceptance rates far from the 0.2–0.5 range indicate the ladder spacing should be adjusted; see geometric_ladder.

UnitCellMC.geometric_ladder — Function
geometric_ladder(T_min, T_max, n)

Return n geometrically spaced temperatures from T_min to T_max (sorted ascending) — the standard starting point for the temperature ladder of a tempering_sweep. Geometric spacing puts equal ratio between neighbors, which roughly equalizes swap acceptance rates when the heat capacity varies slowly; refine from the reported acceptances when it does not.

Throws

ArgumentError if T_min is not positive, if T_max <= T_min, or if n < 2.

Returns

A Vector{Float64} of length n with Ts[1] ≈ T_min and Ts[end] ≈ T_max (up to floating-point rounding of exp ∘ log).

UnitCellMC.swap_pass! — Function
swap_pass!(states, betas, stats, pass, rng)

Attempt exchanges of the configurations of neighboring replicas in a parallel tempering ladder, recording the outcome per adjacent pair in stats (see SwapStats).

states[i] is the configuration currently simulated at inverse temperature betas[i]; a swap exchanges the configurations (the states array entries are exchanged, so each replica keeps its fixed temperature and the cached energy travels with the configuration), accepted with the Metropolis criterion min(1, exp(x)) where x = (betas[i] - betas[j]) * (states[i].energy - states[j].energy), evaluated as log(rand(rng)) < x to avoid overflow. The cached running energies are used directly, so each attempt is O(1).

To preserve detailed balance while giving every adjacent pair equal opportunity, the pass alternates its pairing by pass (the count of swap passes so far, starting at 1): odd passes attempt pairs (1, 2), (3, 4), …, even passes (2, 3), (4, 5), …. Draws come only from rng, consumed in a fixed serial order, so results are independent of thread count.

Returns

states, with the accepted exchanges applied in place.

UnitCellMC.merge_containers — Function
merge_containers(containers)

Merge the binned measurement data of several filled MeasurementContainers — e.g. from n_runs independent run_simulations at the same temperature — into a single container whose data holds the concatenation of all runs' bins. Analysis on the merged container therefore pools all runs, and error estimates reflect the variance between independent runs as well as within them.

The containers must record the same observables and diagnostics, keep the same unbinned time series, use the same bin_size, and compute the same derived quantities — each in any order (e.g. built with the same measurements/diagnostics/time_series arguments and binning, regardless of request order); an ArgumentError is thrown otherwise — pooling bins of different sizes would silently weight unequal-quality averages equally, and adopting the first container's derived set would silently gain or lose quantities in the pooled analysis. Containers holding different numbers of equal-size bins (say, an already-merged container and a fresh run) merge fine, since equal-size bins stay equal-weight. A container holding a partially filled bin (e.g. from an aborted run) is rejected with an ArgumentError, since the incomplete bin cannot be pooled and would otherwise be silently dropped. The time series are concatenated too, with each run's length stored in chain_lengths so autocorrelations never straddle runs. Measuring further into the merged container keeps working: the new samples count as one more chain (see chain_lengths_with_tail).

Returns

A new MeasurementContainer holding the concatenation of all input bins (length(containers) * n_bins when each input holds n_bins bins), ready for analyze. Its vectors are freshly allocated (a single-container merge copies rather than aliases its input), so measuring further into an input container never mutates the merged one, or vice versa.

UnitCellMC.autotune_binning — Function
autotune_binning(algorithm, model, geometry, state, Ts;
                 n_thermalization = 1_000, n_pilot = 5_000,
                 measurements = Symbol[], observables = nothing,
                 bin_factor = 10, n_unmeasured = nothing,
                 window = 6.0, max_lag = nothing,
                 rng = Random.default_rng())

Choose n_unmeasured and the bin size from the data instead of guessing: run a short pilot simulation at each temperature in Ts, measuring after every sweep, estimate the integrated autocorrelation time τ (in sweeps) of each observable with autocorrelation, and convert the slowest one into (bin_size, n_unmeasured) with recommended_binning.

Autocorrelation times grow strongly near a phase transition (critical slowing down, τ ∼ L^z) and, for local updates, at low temperature, so pass every temperature of a planned sweep_Ts (or at least those near the critical point and the lowest one). The pilot visits Ts in the order given and carries state from one temperature to the next, like sweep_Ts with simulated_annealing = true; state is mutated.

Keywords

  • n_thermalization: Warmup sweeps before each pilot measurement run.
  • n_pilot: Pilot measurement sweeps per temperature. The default maximum lag (n_pilot ÷ 10) resolves τ up to about n_pilot / 60 sweeps.
  • measurements: Optional measurements to include in the pilot, as for MeasurementContainer (e.g. [:abs_magnetization]).
  • observables: Names of the observables whose τ determines the recommendation. Only these keep an unbinned history during the pilot. Default: all scalar observables (vector-valued ones such as :correlation are memory-hungry and must be listed explicitly). For the zero-field Ising model you may want to exclude the signed :magnetization, whose τ at low temperature is the (often astronomically long) time to tunnel between the ±m ground states rather than the relaxation time of the physical quantities.
  • bin_factor, n_unmeasured: Passed to recommended_binning.
  • window, max_lag: Passed to autocorrelation.
  • rng: Random number generator for the pilot runs. Defaults to the task-local global RNG, so Random.seed! makes the recommendation reproducible.

Returns

A named tuple with fields

  • bin_size, n_unmeasured: The recommendation. Use n_measurements = bin_size * n_bins in production runs.
  • tau: The slowest integrated autocorrelation time used (in sweeps).
  • T, observable: Where tau was found.
  • per_temperature: For each T in Ts, a Dict mapping observable name to its AutocorrelationResult (times in sweeps).

If an observable's τ could not be resolved within the pilot, a warning is emitted and its lower bound (tau_lower_bound) is used, so the recommendation may still be too small: increase n_pilot in that case. Observables that did not change at all during the pilot (frozen dynamics) are ignored with a warning, as are series whose element type autocorrelation cannot analyze (e.g. matrix-valued observables).

Throws

ArgumentError for invalid arguments, or if no selected observable fluctuated during the pilot (so no autocorrelation time could be estimated).

Reproducibility

UnitCellMC.set_global_seed! — Function
set_global_seed!(seed = rand(Random.RandomDevice(), UInt32))

Seed Julia's global (task-local) RNG with seed via Random.seed! and record it, so that the result writers (save_results, save_sweep_results, and therefore sweep_Ts) store it in metadata.txt. Call it once near the start of a script: every random number drawn afterwards (initial states, autotuning pilots, and all parallel runs of sweep_Ts) then follows from seed, and rerunning the script with the same seed, inputs, and Julia version reproduces the results exactly, for any number of threads.

Without an argument a fresh seed is drawn from the operating system's entropy source, so even an unplanned run can be recreated from its metadata.

Seeding with Random.seed! directly also makes runs reproducible, but the seed is then not known to UnitCellMC and is recorded as unknown (or, if set_global_seed! was called earlier in the session, as that earlier seed, which no longer describes the run), so prefer this function.

Returns

The seed that was set.
